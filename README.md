Лабораторная работа №7: Архитектура, слои и DDD-lite

Структура проекта:

1. **Domain слой** - доменная модель и бизнес-правила
   - `Order` - сущность заказа
   - `OrderLine` - элемент заказа (часть агрегата)
   - `Money` - value object для денежных сумм
   - `OrderStatus` - перечисление статусов заказа

2. **Application слой** - use case и интерфейсы
   - `PayOrderUseCase` - основная бизнес-операция оплаты заказа
   - `OrderRepository` - интерфейс репозитория заказов
   - `PaymentGateway` - интерфейс платежного шлюза

3. **Infrastructure слой** - реализации интерфейсов
   - `InMemoryOrderRepository` - репозиторий в памяти
   - `FakePaymentGateway` - фейковый платежный шлюз

4. **Tests** - тесты use case
   - Тестирование всех бизнес-правил и инвариантов

Инварианты доменной модели:

1. Нельзя оплатить пустой заказ
2. Нельзя оплатить заказ повторно
3. После оплаты нельзя менять строки заказа
4. Итоговая сумма равна сумме строк

Запуск тестов:
pytest tests/
